# LLM 推理中 KV Cache 的工作原理及其显存优化

## 核心结论
1. KV Cache 是通过缓存注意力机制中的 Key 和 Value 向量，避免重复计算，显著提升 LLM 推理速度和降低显存占用的关键机制。
2. 通过将缓存划分为固定大小的页，使用 INT8 或 INT4 量化技术，引入稀疏矩阵减少缓存规模，以及将常用提示的 KV 缓存持久化到磁盘，可以有效优化显存占用。
3. 在长序列生成和多请求处理中，KV Cache 显存占用问题尤为突出，现有优化方法如 MQA/GQA 和 StreamingLLM 在模型训练阶段设定，效果有限。
4. 通过存储向量的方向和缩放因子，实现高效推理，是未来优化 KV Cache 显存占用的重要方向。

## 各维度发现
### 定义与功能
KV Cache 是在 LLM 推理过程中缓存自注意力层的中间结果（键和值），以避免重复计算。它通过缓存历史 token 的 Key 和 Value，使得每次生成新 token 时只需计算新的 query 向量与缓存的 Key/Value 进行注意力计算，从而将时间复杂度从 O(n²) 降低到 O(n)。在多个主流推理框架中被广泛使用，如 vLLM、TensorRT-LLM 等。它虽然提高了推理效率，但也带来了显存压力 [3]。

### 性能影响
KV Cache 在 LLM 推理中占据大量显存，尤其在长序列生成和多请求处理中影响显著。现有系统可能浪费 60%-80% 的显存，主要浪费在 KV Cache 上。KV Cache 的显存占用计算公式为 $2 	imes 4nh + 2 	imes 16$ 字节，其中 $n$ 为解码层数量，$h$ 为头数。文献 [5] 提出了一种优化策略，通过存储向量的方向和缩放因子，实现高效推理。研究显示，键值缓存（KV Cache）在大型语言模型（LLM）推理中扮演着关键角色，通过存储注意力机制的中间状态，显著提升了推理速度，但同时也带来了巨大的内存开销。现有系统中，KV Cache 的内存占用可能达到数十 GB，严重制约了模型的吞吐量、上下文长度和并发处理能力 [2]。

### 优化方法
为了解决显存超出问题，可以将缓存划分为固定大小的页，通过交换机制动态加载所需页；使用 INT8 或 INT4 量化技术；引入稀疏矩阵减少缓存规模；将常用提示的 KV 缓存持久化到磁盘。研究 [1] 指出，现有优化方法如 MQA/GQA 和 StreamingLLM 在模型训练阶段设定，若模型已训练完成则效果不佳。文献 [14] 深入探讨了 KV Cache 优化方法，提出通过存储向量的方向和缩放因子，实现高效推理。研究 [16] 漫谈了 KV Cache 优化方法，指出 StreamingLLM 是一种有效的显存管理方法 [16]。

### 案例研究
以 LLaMA-7B 为例，生成 1024 个 token 时，KV 缓存约占用 1.2GB 显存。为解决显存超出问题，可以将缓存划分为固定大小的页，通过交换机制动态加载所需页；使用 INT8 或 INT4 量化技术；引入稀疏矩阵减少缓存规模；将常用提示的 KV 缓存持久化到磁盘。研究 [3] 显示，键值缓存（KV Cache）在大型语言模型（LLM）推理中扮演着关键角色，通过存储注意力机制的中间状态，显著提升了推理速度，但同时也带来了巨大的内存开销。现有系统中，KV Cache 的内存占用可能达到数十 GB，严重制约了模型的吞吐量、上下文长度和并发处理能力 [2]。
